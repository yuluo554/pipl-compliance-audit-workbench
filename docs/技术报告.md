# 个人信息保护合规审计工作台 —— 技术报告

> 版本：M5（桌面交付 + 报告导出）收口版　|　日期：2026-10-13
> 配套文档：[plan/00 总览](../plan/00-README总览.md)、[plan/04 模块详设](../plan/04-模块详设.md)、[data/README 数据台账](../data/README.md)

## 一、项目定位

本工作台面向《个人信息保护合规审计管理办法》（网信办令第 18 号）落地场景，把"是否触发审计义务"
与"27 项审查要点的逐项四态判定"做成**确定性、可复核、可复现**的本地工具：全本地运行、零上传、
无系统时钟依赖、产物逐字节可复现。它输出的是**合规检查发现**，不构成法律意见。

三个不变量贯穿全部里程碑：

1. **判定只在引擎**：门槛比较与四态映射由规则包数据驱动，界面/报告/基准一律只消费引擎产出；
2. **未核对不得生效**：`status != verified` 或缺出处的条目由单点门控拒绝，不进判定路径；
3. **确定性**：规则包、真值库、报告产物均无系统时间戳，同输入重跑逐字节一致。

## 二、分层架构

```
表现层   cli.py（argparse 子命令，退出码 0/1/2/3）   gui/（PySide6，optional extra）
                        │
编排层   engine/pipeline.py  ← 唯一编排源 compute_audit()
                        │
核心层   rules/(loader,model)  engine/(thresholds,checklist,remediation)
         evidence/  report/(model,markdown,docxutil)  benchmark/(cases,runner)
                        │
数据     data/rules  data/samples  data/truth  data/knowledge/raw（不入发行）
```

**依赖纪律**（AST 静态守门 G3）：严格核心层任何位置都不得 import PySide6 / python-docx /
openpyxl；GUI 与 DOCX/XLSX 渲染器属**惰性边界层**，重件只能在函数体内导入。核心通路因此在
未安装任何 optional extra 时仍可完整运行（`check` / `bench` / `report -o x.md`）。

**接入纪律**（守门 G10/G12）：模块"有实现"不等于"接上了"。`attach_evidence` / `export_draft` /
`import_draft` / `apply_ledger` / `render_to_file` 均须有非测试调用点，否则守门失败。

## 三、确定性内核

### 3.1 门槛判定

门槛值、算子、义务类型（`effect`）全部读自规则包；比较在整数域进行，无浮点尾差。命中结果按
`effect` **分栏**呈现：

- `obligations`（无条件义务）：周期性义务（带频次）/ 持续性义务；
- `conditional_triggers`（条件触发）：保护部门**可以要求**委托专业机构，非处理者无条件义务。

分栏是硬约束：条件触发不得冒充处理者无条件义务，报告与结论均分节呈现。`triggered` 仅表示
"命中任一门槛（含条件触发）"。

### 3.2 四态判定与缺项口径

单项状态为 `compliant` / `partial` / `noncompliant` / `not_applicable` / `unknown`；汇总在
**无 applicable 项**时记 `not_assessed`，绝不输出 `compliant`。`unknown`（未观测）与
`not_applicable`（不适用）都不计违规、不进分母。

**缺项口径**是易错点：指引十九、二十、二十四为"应当制定"的**无条件义务**，未制定即
**不符合**；若记成"不适用"会把"没做"记成"不用做"，虚高合规结论。保留 `not_applicable` 分支的
仅限原文确有"不适用情形"者。

### 3.3 auto 映射

auto 项的"取值 → 四态"映射写在规则包的 `auto_mapping`（按序取首个命中，末条 `default` 兜底），
引擎零业务字面量。规则包未给映射时退化为旧口径（非空=compliant / 空=noncompliant），
以兼容未细化的示例包。

## 四、数据与溯源

- **规则包**（`data/rules/`）：由 `tools/gen_rulesets.py` 从单一年度模板 + 依据差异点生成，
  禁手改产物；重跑须逐字节一致（守门 G5）。
- **真值库**（`data/truth/`）：42 例合成审计场景，含**逐项真值** `expected.item_states`
  （42 × 26 = 1092 条观测），由生成器**独立推导**（非引擎计算），基准期不现算真值，
  避免"引擎算真值再自比"的自证循环。
- **官方原文快照**（`data/knowledge/raw/`）：仅用于核对留档，**不入打包白名单**（版权红线）。
- 全部合成数据为虚构值，禁真实个人信息入库（守门 G9 校验）。

## 五、评测基准

一条命令跑全四类套件：`paudit bench` → **B1 18 / B2 26 / B3 42 / B4 120 = 206/206**，
纯计算约 0.014 秒。

三项门指标显式给出，并进退出码（未过门 → exit 1）：

| 指标 | 口径 | 实测值 | 门值 |
|---|---|---|---|
| 触发判定准确率 | 门槛命中判定 vs 真值 | 1.0000（54/54） | ≥ 0.95 |
| 四态准确率 | 逐项四态 vs 冻结真值 | 1.0000（1092/1092） | ≥ 0.95 |
| 误报率 | 误报数 ÷ 真值非问题项数 | 0.0000（0/982） | ≤ 0 |

**二元口径**：问题 = `partial` ∪ `noncompliant`；误报 = 真值非问题而引擎判问题；漏报对称；
分母为 0 记 0。该口径的唯一实现源是 `benchmark/cases.py` 的 `confusion()`，测试、基准与真值
生成共用，防"基准说达标、测试说不过"的双口径漂移。

## 六、桌面交付（M5）

### 6.1 GUI 四页签

PySide6 桌面应用分四页签，**只消费引擎 API**：触发判定（门槛结论 + 义务分栏）、检查单
（全项四态 + 依据）、证据链（挂证 + 台账填写）、报告导出（三格式 + 两模板）。

界面拆为**数据面**与**Qt 层**：

- `gui/session.py`：纯 Python，零 Qt 依赖，只调 `compute_audit` / `attach_evidence` /
  `apply_ledger` / `export_draft` / `render_to_file`，零判定逻辑。因此可用普通 pytest 无头覆盖
  业务正确性，不必起 QApplication；
- `gui/main_window.py`：Qt 装配层，只做"读 session → 填控件"与"读控件 → 调 session"。

界面与 CLI 共享同一编排源与同一份引擎产出，故两者结论不会漂移。挂证与台账填写**不改变判定
结论**（与 CLI 同口径），编辑后清除陈旧自指纹。

### 6.2 打包

PyInstaller **onedir 双 exe**（GUI + CLI），spec 落在 `tools/`。数据白名单由
`tools/build_data.py` 单一实现源展开，**版权红线三重守门**：

1. 构建器内直接抛错：白名单展开命中禁区即 `BuildError`（构建前拦截）；
2. spec 文本守门：守门测试断言 spec 不含禁区路径字面量；
3. 构建后 dist 扫描：遍历产物树，命中禁区目录/文件名特征即报错。

实测：两个 exe 均在**干净目录**独立运行——CLI exe 跑出 206/206 并导出 DOCX，GUI exe 正常进入
事件循环；产物树内 `data/` 只含 `rules/`、`samples/`、`truth/`，无任何官方原文快照。
Qt 打包常见坑（缺 `platforms/qwindows.dll`）经检查已正确收录。

### 6.3 报告导出（MD/DOCX/XLSX，模板两版）

三格式共用 `report/model.py` 的**单一内容源**（结构化块），渲染器只做"块 → 载体语法"映射，
故同一底稿在三产物里结论一致。模板两版：企业自审版 / 第三方机构版（后者加核查方式列与
签署栏）。

**逐字节可复现**是 M5 的门槛项。python-docx 与 openpyxl 落盘时会写入当前时间（zip 条目时间戳、
`docProps/core.xml` 的 created/modified），同输入两次导出字节不同。处置为落盘后统一收口
（`report/docxutil.py`，纯标准库、全通路复用）：

1. 全部 zip 条目时间戳固定、`create_system=0`（跨平台一致）；
2. `docProps/core.xml` 的 created/modified 钉成固定值（openpyxl 在 save 时才覆盖，故必须
   落盘后改写，写入前设置无效）；
3. 保持条目顺序与压缩方式不变（不重排，避免引入额外差异源）。

实测六种"格式 × 模板"组合均逐字节可复现（含跨时间间隔的两次导出）。

## 十、局限与诚实记录

- **两标准的章节条号未逐条核对**：官方全文预览为受版权保护的打乱页图像、许可协议禁复制/
  下载，工具**不绕过**版权保护。26 条检查项一律挂办法附件《审计指引》条号，**不引用两标准
  章节号**（宁缺勿造）。
- **CI 已真跑（M6）**：此前 M0–M5 期间无远端，各里程碑如实只记"本地等价校验"（**不记"CI 绿"**）。
  M6 建仓首推后 CI 真跑：首跑 run `38479282274` **失败**（Windows 运行器 cp1252 locale），
  修复后复跑 run `38480212333` **三矩阵全绿**——真实结论已据实回写，首跑失败与根因一并留在
  本节（见 §八）。
- **干净环境验证抓到真实缺陷（M6）**：`git archive` 树逐字执行 README 快速开始，抓出
  README 引用不存在的输入夹具、缺 `[report]` extra 时报告用例硬失败、CI 未装 `[report]`
  致可复现门静默跳过三处——均已修并固化为 G13 端到端回归。
- **界面为单机工作台**：不含多用户/权限/服务端；数据与产物均在用户本机。
- **判定依据限于已核对条款**：未挂原文核对的义务不建检查项，故检查项覆盖的是当前已核对
  范围，不宣称穷尽。
