# 05 数据计划与里程碑

> 上游：[04-模块详设.md](04-模块详设.md)。本文定检查项库入库策略、合成场景生成器、M0–M6 的 DoD。
> 版本：v1（M0 定稿，2026-10-13）

## 一、数据入库策略（数据先行）

### 1.1 规则包（`data/rules/`）

- **组织形态**：`依据文件 × 版本`。首期三份依据 → `ruleset-pipl-audit-2025.json`（可扩展为多版本）。
- **产出方式**：`tools/gen_rulesets.py` 由**单一年度模板 + 依据差异点参数化**生成；**禁手改产物**，改需求走生成器整目录重生成。
- **确定性**：自研 splitmix64 RNG（若需随机则用固定 seed）；禁 stdlib random/set 迭代序/系统时钟；产物无时间戳；配"再生成位图一致"守门测试（G5）。
- **溯源**：每条门槛/检查项挂 `clause`{basis, article, point} + `status` + `source`{channel, url, checked_at}。**双出处键**：数值出处与条号出处分开挂（官方表原文可能不含具体数值列，需另找附件或解读页）。
- **零政策字面量**：门槛数值收编为禁用 token（词边界）扫源码（G1）。

### 1.2 检查单（`data/checklists/` 或并入 ruleset.checklist）

- 26 项级，按四层分布（制度/流程/技术/响应）；每条含编号/类别/层级/依据条款/核查方式/判定标准/证据要求/status。
- **未挂原文核对不得生效**：`status=pending` 的检查项由 `effective_ruleset()` 门控拒绝，不进判定路径。
- **不编造标准内容**：核对记录未覆盖的义务不建检查项（宁缺勿造）；`check_types` 若某类不存在，基准如实写"该类用例未生成"（不假装覆盖）。

### 1.3 合成审计场景 + 真值库（`data/truth/`）

- `tools/gen_scenarios.py` 程序化构造：输入参数卡 + **期望审计判定真值**（是否触发、应判四态、问题分级）。
- **真值语义一次定清**：`expected`（主期望）+ `also_expect`（隐含中间量）；评测按"全部非 pass 字段集"对账；对账语义收成单一实现源 `benchmark/cases.py`。
- **合成数据纪律**：假身份白名单（保留测试号段 `19900000000` 类）、虚构企业名、符合校验位算法但虚构的信用代码；**禁止真实个人信息入库**。 <!-- audit-allow: 合成测试号段白名单，非真实号码 -->
- 固定 seed 可复现；产出物 sha256 留档。

### 1.4 官方原文快照（`data/knowledge/raw/`）

- 官方公文/标准页面快照（著作权法第五条官方文件不适用版权保护）；
- **版权红线**：该目录**不入打包白名单**（构建器内直接抛错 + spec 文本守门 + 构建后 dist 禁区扫描三重守门）。

## 二、依据核对流程（逐条挂出处）

1. **查证触发线**：结论依赖法规数值/条号 → 第一步就是外部查证（官方直连优先）；
2. **直连落盘**：`curl -s -L <url> --max-time 25` 落盘后本地提取，不靠摘要转述；
3. **两渠道全败 → 标"待核对"继续推进**（不空转、不编造）；
4. **入库每条挂出处**：规范号 + 条号 + 渠道 + 抓取日期；
5. **查证记录进台账**：`data/README.md` §二 逐条 ✅/⬜ + 渠道；已查渠道记入决策记录。
