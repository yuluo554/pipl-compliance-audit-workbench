# 02 需求解读（痛点 → 能力转译 / FR 清单 / NFR / 边界守卫）

> 上游：[01-题目详细定义.md](01-题目详细定义.md) v1。本文把题面转译为可执行的功能需求（FR）与非功能需求（NFR），并锁定边界守卫。
> 版本：v1（M0 定稿，2026-10-13）

## 一、痛点 → 能力转译

| 企业侧真实痛点 | 本工具提供的能力 | 对应 FR |
|---|---|---|
| 不知道自己是否触发审计义务、多久做一次 | 确定性门槛引擎：按处理规模/敏感信息/处理者类型判"是否触发 + 频次 + 是否需专业机构"，结论挂条款依据，边界值枚举验证 | FR-1 |
| 审计要查哪些项、依据是什么，靠人翻办法和标准 | 版本化审计规则集：把办法+标准编码为结构化检查项，每条挂条款依据与 status | FR-2 |
| 检查结论无法回溯到条款、无法复现 | 依据联动：每个结论输出条号；报告头固定输出规则包坐标（依据版本+版本号+生成时间） | FR-2 / FR-5 |
| 查出问题留不住证据、复查时对不上 | 证据链：结论挂本地证据引用 + sha256 指纹固化进底稿，报告附证据清单与指纹 | FR-3 |
| 问题没有分级、整改没有台账、跨会话做不完 | 问题分级（高/中/低/建议，挂条款依据）+ 整改台账 + 底稿导入导出 | FR-4 |
| 报告靠手写、格式不统一、不可核证 | 一键导出合规审计报告（MD/DOCX/XLSX），模板可配置（企业自审版/第三方机构版） | FR-5 |
| 规则随办法/标准修订会过期 | 规则包按 `依据文件 × 版本` 组织，条款变更即升版本；切换规则版本即切换检查单与门槛值 | FR-6 |
| 怕"没查出问题"被误读成"合规" | 判定语义分层：未观测≠缺失、不适用≠违规；一条都没评 → `not_assessed`（绝不输出 compliant） | FR-2 / FR-5 |
| 担心敏感数据外泄 | 全本地处理存储、零上传、默认不联网；合成/脱敏数据纪律；免责声明强制 | NFR-1 / NFR-2 |

## 二、FR 功能清单（带优先级）

优先级：P0 = 首期必做（M0–M5），P1 = 首期应做，P2 = 首期可选/留扩展。

### FR-1 审计触发与频次判定引擎（P0）

- FR-1.1 输入参数卡：`subject_type`（处理者类型）、`scale`（处理个人信息人数规模）、`sensitive`（是否处理敏感个人信息）等，全部字段与取值来自规则包，不在代码中硬编码。
- FR-1.2 确定性判定（条款已核对，见 data/README §二·1）：是否触发定期合规审计义务（办法**第四条**：处理**超过 1000 万人**每两年至少一次）；是否须指定个人信息保护负责人（**第十二条**：**100 万人以上**）；是否属保护部门可要求委托专业机构审计的情形（**第五条**）。
- FR-1.3 每条判定结论挂条款依据（`依据号 + 条号 + 要点`），结论与依据同屏输出。
- FR-1.4 边界值显式处理：门槛"恰好等于""上/下 1 人"在基准中枚举验证。
- FR-1.5 门槛值与判定参数一律从规则包读取；引擎、基准、前端源码中不得出现门槛字面量（零政策字面量门禁，见 NFR-5）。

### FR-2 审计检查单引擎（P0）

- FR-2.1 结构化检查项模型：编号、类别、层级、条款依据、核查方式（auto/manual）、判定标准、证据要求、status。
- FR-2.2 分层：制度层（政策/组织/培训）、流程层（告知同意/最小必要/委托处理/共享转让）、技术层（访问控制/加密/去标识化/日志）、响应层（个人权利响应/安全事件/投诉处理）。**检查项以办法附件《审计指引》27 项审查要点为骨架**（条款依据已核对）。
- FR-2.3 自动核查项：可从结构化输入表单判定（如"是否提供撤回同意入口"由字段判定）。
- FR-2.4 人工核查项：需审计员录入结论与证据。
- FR-2.5 判定语义（**关键**）：
  - 已评 → 四态：`compliant`（符合）/ `partial`（部分符合）/ `noncompliant`（不符合）/ `not_applicable`（不适用）；
  - **不适用 ≠ 违规**：门控（`only_if`）判不适用记 `skipped`，不计违规、不计分母；
  - **未观测 ≠ 缺失**：人工项未录入记 `unknown`（计入"待人工确认"，不计违规）；
  - **一条规则都不适用/都未评 → 汇总级 `not_assessed`（未评估）**，绝不输出成 `compliant`。
- FR-2.6 检查项库 JSON 化，每条挂条款依据与 status；`status=pending` 的检查项不得进入判定路径（引擎入口单点门控）。

### FR-3 证据链留痕（P0）

- FR-3.1 每个检查结论可挂载证据（本地文件引用：截图/文档/日志片段），记录来源、采集时间、责任人。
- FR-3.2 不可篡改：证据条目计算 sha256 指纹随审计底稿固化；报告导出附证据清单与指纹，供复查对照。
- FR-3.3 审计底稿可整体导出/导入（JSON），支持跨会话续做与复核。
- FR-3.4 底稿自身（导出产物）计算 sha256 进 `evidence.json`——"底稿被改动即可检出"。
- FR-3.5 证据仅存**结构说明与指纹**（字段/类型/大小/时间），不落真实内容副本；路径按脱敏纪律登记。

### FR-4 问题分级与整改跟踪（P1）

- FR-4.1 按严重程度分级：高风险/中风险/低风险/建议，分级标准挂条款依据。
- FR-4.2 整改台账：问题 → 依据条款 → 整改建议 → 责任人 → 期限 → 状态，支持导出。
- FR-4.3 伦理框架：输出为"合规检查发现"，明确声明不构成法律意见。

### FR-5 审计报告导出（P0）

- FR-5.1 一键导出合规审计报告：审计范围、依据清单、触发判定结论、检查单全项结果、问题清单与整改台账、证据清单与指纹。
- FR-5.2 报告头固定输出**规则包坐标**（依据版本 + 版本号 + 生成时间），保证可复现与可比对。
- FR-5.3 报告模板可配置：企业自审版 / 第三方机构版。
- FR-5.4 产物形态：Markdown（核心层，零第三方依赖）+ DOCX/XLSX（optional extra）。
- FR-5.5 报告产物逐字节可复现（相同输入两次导出字节一致；zip 型产物钉死内部时间戳）。

### FR-6 版本化审计规则集（P0）

- FR-6.1 规则包按 `依据文件 × 版本` 组织，每条挂文号/标准号与 status（`verified`/`pending`）。
- FR-6.2 规则包 JSON 化、生成器产出、禁手改；配"再生成逐字节一致"守门测试。
- FR-6.3 依据联动：每项检查结论可回溯到具体条款。
- FR-6.4 切换规则版本即切换检查单与门槛值（版本选择进报告头坐标）。

### FR-7 内置评测基准（P0）

- FR-7.1 门槛边界基准：办法门槛（**1000 万人**定期审计、**100 万人**负责人）的边界值（恰好等于、上下 1 人）枚举验证判定正确性。
- FR-7.2 检查项自洽基准：规则包条款引用完整性、四态判定逻辑覆盖、证据要求非空。
- FR-7.3 合成审计场景基准：程序化构造带真值的合成审计场景（如"某企业处理 120 万人信息但未做审计"应判触发+未达标），零 API 依赖可重复。
- FR-7.4 四类 runner 一条命令跑全，退出码 0 达标 / 1 未达标或门控拦截 / 2 用法错误；全量单次 < 1 秒。

### FR-8 交付形态（P0）

- FR-8.1 CLI 双入口：`paudit`（主命令）+ 子命令 `check` / `scan` / `bench` / `report` / `gui`。
- FR-8.2 桌面应用（PySide6）：多页签只消费既有引擎 API，不另起第二套行为。
- FR-8.3 PyInstaller onedir 双 exe（GUI console=False + CLI console=True），Release 附安装包。
- FR-8.4 冻结态自检通路 `--selftest <输出文件>`，供脚本化验收窗口 exe。

## 三、NFR 非功能需求

| 编号 | 需求 | 验收方式 |
|---|---|---|
| NFR-1 | **全本地处理存储、零上传、默认不联网**：核心层与基准零网络调用；依赖分层无联网必需件 | 测试断言核心层 import 无网络库；基准离线可跑 |
| NFR-2 | **数据纪律**：审计场景一律合成/脱敏，禁真实个人信息入库；假号段/虚构身份白名单登记 | 数据台账 + 脱敏守门测试 |
| NFR-3 | **确定性可复现**：生成器自研确定性 RNG（splitmix64）、禁 stdlib random/set 迭代序/系统时钟；冻结产物无时间戳，两次运行逐字节一致 | 再生成位级一致守门测试 + EOL 守门 |
| NFR-4 | **核心层零第三方依赖**：`paudit` 核心（规则加载/门槛/检查单/证据/报告-MD/基准）仅用标准库；GUI/文档导出/打包为 optional extras | CI core-only 矩阵断言核心层可跑；AST 静态守门断言核心层不 import 重件 |
| NFR-5 | **零政策字面量门禁**：门槛数值/条款号数值不得出现在引擎/基准/前端源码（含注释与文档字符串）；数值只能来自规则包 | 门禁扫描测试（token 词边界扫描） |
| NFR-6 | **未核对不生效**：规则包 `status=pending` 条目不得进入判定路径 | 门控单测（pending 条目被拒） |
| NFR-7 | **免责声明强制**：CLI/报告/GUI 输出均含"不构成法律意见"声明 | 输出断言测试 |
| NFR-8 | **跨平台 CI 绿**：windows×{3.8,3.12} + ubuntu×{3.12} 三矩阵；`.gitattributes` eol=lf；workflow 可解析守门 | CI + workflow 解析守门测试 |
| NFR-9 | **诚实交付纪律**：无远端时 DoD 只写"本地等价校验"，不写"CI 绿" | 计划文档审计 |

## 四、边界与非目标（守卫清单）

**不做（正面竞争无优势或超范围）**：
- ❌ 不做 App/小程序 API 调用的动态/静态技术检测（PrivacySentry 等已占该细分）；
- ❌ 不做法律意见出具（工具输出为合规检查发现，非法律判定）；
- ❌ 不做自动化数据爬取核查、不对接监管申报接口；
- ❌ 首期不接办法/标准之外的其他依据（其余配套标准留扩展）；
- ❌ 不复制姊妹项目代码；文档不提其余项目业务领域。

**首期范围（硬边界）**：
- 依据限定三份：《审计办法》令第 18 号 + GB/T 35273-2020 核心章节 + GB/T 42574-2023 告知同意；
- 检查单目标 53 项级（M1 逐条挂原文核对后落库）；
- 交付形态限定 Windows 桌面 + CLI 双形态。

**合规红线（守卫）**：
- 全本地、零上传、默认不联网；
- 未挂原文核对（status=pending）不得落库/生效/进入判定路径；
- 输出强制免责声明；
- 审计场景一律合成/脱敏数据。
