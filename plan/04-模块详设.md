# 04 模块详设

> 上游：[03-架构与技术选型.md](03-架构与技术选型.md)。本文定规则包 schema、检查项模型、门槛判定语义、证据与报告模板。
> 版本：v1（M0 定稿，2026-10-13）

## 一、规则包 schema（`data/rules/ruleset-*.json`）

```jsonc
{
  "schema_version": "1.0",
  "ruleset_id": "pipl-audit-2025",          // 规则集稳定身份键（跨版本不变）
  "version": "2025.1",                      // 规则包版本（条款变更即升）
  "generated_at": "2026-10-13T00:00:00Z",   // 生成器固定值（非系统时钟）
  "basis": [                                // 依据清单（报告头坐标）
    {"code": "网信办令第18号", "title": "个人信息保护合规审计管理办法",
     "effective_date": "2025-05-01", "status": "verified", "source": {...}},
    {"code": "GB/T 35273-2020", "title": "信息安全技术 个人信息安全规范",
     "effective_date": "2020-10-01", "status": "verified", "source": {...}},
    {"code": "GB/T 42574-2023", "title": "信息安全技术 个人信息处理中告知和同意的实施指南",
     "effective_date": "2023-12-01", "status": "verified", "source": {...}},
  ],
  "thresholds": [ /* 门槛规则数组，见 §二 */ ],
  "checklist":  [ /* 检查项数组，见 §三 */ ]
}
```

**status 语义**（全库统一）：
- `verified`：已挂官方原文核对，必须带 `source`{`channel`, `url`, `checked_at`}；
- `pending`：待核对，**不得进入判定路径**（`effective_ruleset()` 门控拒绝）。
- `source.url` 可空（如标准全文公开页需登录），但 `channel` 与 `checked_at` 必填。

## 二、门槛规则模型（`thresholds[]`）

门槛用**声明式规则**表达，而非代码分支（防硬编码，满足 NFR-5）：

```jsonc
{
  "id": "TH-SCALE-PERIODIC",
  "param": "scale",              // 输入参数名
  "op": ">",                     // 比较算子: > >= < <= == !=
  "value": 10000000,             // 门槛值（数值只能在此出现）
  "conclusion": "trigger_periodic_audit",   // 结论码
  "effect": "periodic_obligation",  // 义务类型（M2）：见下
  "frequency": "每两年至少开展一次合规审计",   // 适用频次（来自条款要点）
  "clause": {"basis": "网信办令第18号", "article": "第四条", "point": "<条款要点>"},
  "status": "verified",
  "source": {"channel": "cac.gov.cn", "url": "...", "checked_at": "2026-10-13"}
}
```

**义务类型 `effect`（M2 三分判定，数据驱动）**：

| effect | 语义 | 实例 |
|---|---|---|
| `periodic_obligation` | 处理者**无条件**周期性义务（带频次） | 第四条（每两年一次） |
| `standing_obligation` | 处理者**无条件**持续性义务（无频次） | 第十二条（指定负责人） |
| `conditional_institution` | **条件触发**：保护部门"**可以要求**"，非处理者无条件义务 | 第五条（三）（委托专业机构） |

判定结果按 `effect` **分栏呈现**（`obligations` / `conditional_triggers`），结论不混同；
"频次"只取无条件义务栏（条件触发不产生处理者频次义务）。

> 已核对的条款（data/README §一·2）：**第四条** 超过 **1000 万人**每两年一次（`op=">"`）；**第十二条** **100 万人以上**须指定负责人（`op=">="`）；**第五条（三）** 安全事件致 **100 万人以上个人信息 / 10 万人以上敏感个人信息**泄露等，保护部门**可以要求**委托专业机构审计（`op=">="`，**条件触发** `may_require_professional_institution`，非无条件义务）；第五条（一）（二）为定性情形（较大风险/可能侵害众多个人权益），**不建模为数值门槛**。

**判定算法**：门槛引擎按 `param` 取输入值，按 `op`/`value` 求值；命中多个门槛时按**最严格者**（结论严重度序）归并。所有比较都在 `Decimal`/整数域（规模为人数，整数比较，无浮点尾差）。

**边界处理**：`op` 决定边界归属（`>` 不含等于，`>=` 含等于）；"恰好等于门槛""上/下 1 人"由基准枚举验证（FR-7.1）。

## 三、检查项模型（`checklist[]`）

```jsonc
{
  "id": "CHK-PRO-004",
  "category": "流程层",            // 制度层/流程层/技术层/响应层
  "title": "告知义务审查（显著方式/清晰易懂/变更告知）",
  "clause": {"basis": "网信办令第18号", "article": "附件指引4", "point": "<要点>"},
  "method": "auto",               // auto=可结构化判定 / manual=审计员录入
  "auto_field": "notice_before_processing",  // method=auto 时：绑定的输入字段名
  "auto_mapping": [               // M2：取值 → 四态 映射规则（数据驱动，引擎零业务字面量）
    {"match": {"one_of": [true, "complete", "yes"]}, "state": "compliant"},
    {"match": {"equals": "partial"},                 "state": "partial"},
    {"match": {"one_of": ["not_required", "not_applicable"]}, "state": "not_applicable"},
    {"match": {"default": true},                     "state": "noncompliant"}
  ],
  "criteria": "四态判定（…）：逐项核对…。全部满足=符合；部分满足=部分符合；均不满足=不符合；<不适用情形>=不适用。",
  "evidence_required": true,      // 证据要求（自洽基准断言非空）
  "only_if": null,                // 门控：不满足记 not_applicable（不计违规/分母）
  "status": "verified",
  "source": {"channel": "cac.gov.cn", "url": "...", "checked_at": "2026-10-13"}
}
```

> **依据口径（M1 定）**：26 条检查项**统一挂办法附件《审计指引》条号**（原文已核对）。
> 因两标准（GB/T 35273-2020、GB/T 42574-2023）**章节条号未能核对**（官方预览受版权保护、禁复制/下载），
> 检查项**不引用标准章节号**；两标准仅列 `basis` 背景依据（见 data/README §二·4）。
> `auto_field`/`auto_mapping`/`only_if` 为工具内部约定（字段名与取值词表非法规原文）。

**`auto_mapping` 匹配词表（结构性词，M2）**：`{"equals": v}` / `{"one_of": [v…]}` /
`{"empty": bool}` / `{"nonempty": bool}` / `{"default": true}`（兜底）。按序取**首个命中**；
规则表为空时引擎退化为旧口径（非空=compliant / 空=noncompliant），兼容未细化的示例包。

**判定流程**：
1. `effective_ruleset()` 过滤掉 `status=pending` 的检查项（NFR-6）；
2. 对 `method=auto` 项：读参数卡 `auto_field` 值 → 按规则包 `auto_mapping` 映射为四态
   （规则包未给映射时退化：非空=compliant / 空=False → noncompliant）；
3. 对 `method=manual` 项：读底稿中审计员录入结论；未录入 = `unknown`（未观测）；
4. `only_if` 门控（可选）：门控值不满足 → `not_applicable`（skipped），不计违规、不计分母；
5. 汇总：见 §四。

> **M2 缺项口径勘误（重要）**：《审计指引》十九/二十/二十四原文为"**应当**制定内部管理制度 /
> 采取安全技术措施 / 制定应急预案"（二十、二十四又冠以"个人信息处理者应当…"），属**无条件义务**——
> **未制定 = 不符合**，M1 曾误设的"未制定 = 不适用"已勘误（否则会把"没做"记成"不用做"，
> 虚高合规结论）。指引四（六）等的"法定免告知情形"才是真正的不适用情形，保留 `not_applicable` 分支。

## 四、汇总判定语义

```
applicable = 检查项中状态 ∈ {compliant, partial, noncompliant} 的项
if applicable 为空:                      summary = not_assessed   # 绝不输出 compliant
elif 存在 noncompliant:                  summary = noncompliant
elif 存在 partial:                       summary = partial
else:                                    summary = compliant
```

**"没查出问题"与"没检查过"必须可区分**：`unknown`（未观测）计入"待人工确认"计数，不进 `applicable` 分母；`not_applicable` 不计入分母。

## 五、证据链模型

```jsonc
// 底稿 draft.json（M3：顶层扁平规则包坐标，底稿自足可离线重算）
{
  "schema_version": "1.0",
  "ruleset_id": "pipl-audit-2025",
  "ruleset_version": "2025.1",
  "generated_at": "2026-10-13T00:00:00Z",
  "audit_scope": {"subject": "示例企业（虚构）", "period": "2026"},
  "input_card": { "scale": 1200000, "sensitive": true, "subject_type": "processor" },
  "manual_results": { "CHK-DOC-022": {"state": "partial", "note": "…"} },
  "threshold_result": { /* 门槛判定结论 + 依据（obligations / conditional_triggers 分栏） */ },
  "summary": "noncompliant",
  "counts": { /* 四态计数 */ },
  "item_results": [
    {"item_id": "CHK-DOC-019", "state": "noncompliant", "note": "...",
     "evidence": [
       {"evidence_id": "EV-0001", "source": "制度文件截图（结构说明）",
        "collected_at": "2026-10-01", "owner": "审计员A",
        "file_ref": "shot.png", "size": 12345,
        "sha256": "<64hex>"}
     ]}
  ],
  "findings": [ {"finding_id": "F-001", "item_id": "...", "risk": "high",
                 "clause": {...}, "recommendation": "...", "owner": "张负责",
                 "due": "2026-12-31", "status": "in_progress"} ],
  "draft_sha256": "<64hex，导出时写入>",
  "disclaimer": "本工具输出为合规检查发现，不构成法律意见……"
}
```

**指纹固化**：每条证据的 `sha256` 随底稿固化；底稿导出产物自身 sha256 写进随附 `.evidence.json`。

**M3 接入与校验（定稿）**：

| 能力 | 实现 | 纪律 |
|---|---|---|
| 挂证 | `attach_evidence()`（`evidence/__init__.py`）+ CLI `check --evidence 检查项=文件` / `evidence --add` | 只登记文件名与指纹，路径不入底稿正文；挂证前校验检查项存在于规则包与底稿（防挂到未知项） |
| 底稿导出 | `export_draft()`（`check --draft` / `draft export`） | 无时间戳、键排序、LF、写 `draft_sha256` + `.evidence.json` |
| 底稿导入 | `import_draft()`（`draft import`） | **三重校验**：自指纹 → `schema_version` → `ruleset_id`，不匹配**显式报错**（exit 2），不静默降级 |
| 往返一致性 | `verify_draft_consistency()` | 底稿自足（存 `input_card`/`manual_results`），导入时**离线重算结论**并与底稿比对；漂移即失败（exit 1）。挂证/台账不改变结论，故不受其影响 |
| 证据复核 | `evidence --check` | 按"底稿目录 → 当前目录"定位证据文件，重算 sha256 比对；不匹配 exit 1 |
| 编辑后指纹 | `evidence`/`ledger --write-draft` 写回时**清除** `draft_sha256` | 防"看似有效"的陈旧自指纹；需固化时重跑 `draft export` |

> **底稿自足性（M3 关键设计）**：底稿保存 `input_card` 与 `manual_results`，故导入方可**独立重算**结论——
> 这是"导入底稿重算结论 == 导出前结论"可断言的前提（否则只能比对静态文本，检不出语义漂移）。

### §五·2 整改台账模型（M3）

```jsonc
// findings[] 的台账三字段（工具内部约定，非法规原文）
{"owner": "张负责", "due": "2026-12-31", "status": "in_progress"}
```

- **状态枚举**：`open`（待整改，初值）/ `in_progress`（整改中）/ `resolved`（已整改）/ `waived`（已豁免）；
  非法状态**显式报错**（不静默降级）。
- **分级恒挂条款依据**：`risk`（`high`=不符合 / `medium`=部分符合）与 `clause` 由引擎产出；
  台账**只补责任落实**（`owner`/`due`/`status`），**不得覆写**分级与依据（`apply_ledger` 只写这三字段）。
- **可填可导出**：`ledger --apply <JSON|CSV>` 填写；`ledger -o out.csv` 导出（LF、固定列序、按 `finding_id` 升序）；
  导出的 CSV 可直接回读（闭环）。
- **报告联动**：报告第五节呈现台账（状态中文化 + 汇总行：共 N 项 / 已指定责任人 M 项 / 各状态计数）。

## 六、报告模板（两种）

| 节 | 企业自审版 | 第三方机构版 |
|---|---|---|
| 报告头 | 规则包坐标（依据版本+版本号+生成时间） | 同左 + 审计机构/受托信息占位 |
| 审计范围 | 主体/期间/依据清单 | 同左 + 委托事项 |
| 触发判定 | 结论 + 条号 | 同左 |
| 检查单全项 | 全项四态 + 说明 | 同左 + 核查方式标注 |
| 问题清单 | 分级 + 依据条款 | 同左 + 复核人栏 |
| 整改台账 | 问题→建议→责任人→期限→状态 | 同左 |
| 证据清单 | 来源/时间/责任人/指纹 | 同左 |
| 声明 | 免责声明 | 同左 + 签署栏 |

**报告产物确定性**：Markdown 无时间戳（时间取底稿显式字段）；DOCX/XLSX 落盘后统一"固定时间戳 + `create_system=0`"重写 zip 收口（`report/docxutil.py` 供全通路复用）。

**M5 落地（单一内容源 + 三渲染器）**：报告拆为**内容模型**与**渲染器**两层——

| 模块 | 职责 |
|---|---|
| `report/model.py`（核心层） | **单一内容源**：把底稿 + 规则包组装为结构化块（`Heading`/`Para`/`Bullets`/`Table`/`Note`/`Section`/`Report`）；模板只影响抬头、附加列（第三方版加"核查方式"列）与签署栏 |
| `report/markdown.py`（核心层） | 块 → Markdown 语法（表格单元转义 `|` 与换行） |
| `report/docx.py`（optional） | 块 → Word（标题/段落/项目符号/表格）；重件只在函数体内导入 |
| `report/xlsx.py`（optional） | 块 → 固定六工作表（概览/审计依据/触发判定/检查单/问题台账/证据清单） |
| `report/docxutil.py`（核心层，纯标准库） | OOXML 确定性收口：固定 zip 条目时间戳 + `create_system=0` + 固定 `docProps/core.xml` 的 created/modified（openpyxl 在 save 时才覆盖，故必须落盘后改写）；DOCX/XLSX 共用 |

`report/__init__.py` 的 `render_to_file()` 按扩展名分派（`.md`/`.docx`/`.xlsx`），未知扩展名报
输入错误（exit 2），缺 optional extra 报 exit 3。**同一底稿在三种产物里结论一致**（共用内容源），
且六种"格式 × 模板"组合**逐字节可复现**。

**M5 桌面形态（`gui/`）**：界面拆为**纯 Python 数据面** `gui/session.py`（零 Qt、只调引擎 API、
零判定逻辑，可用普通 pytest 无头覆盖）与 **Qt 装配层** `gui/main_window.py`（四页签；重件只在
函数体内导入）。界面与 CLI 共享同一编排源与同一引擎产出，故两者结论不会漂移；挂证与台账填写
**不改变判定结论**。

**M5 发行形态（`tools/*.spec` + `tools/build_data.py`）**：PyInstaller **onedir 双 exe**（GUI + CLI）；
数据白名单由 `build_data.py` 单一实现源展开，**版权红线三重守门**：① 构建前命中禁区即
`BuildError`；② spec 文本守门（不含禁区路径字面量）；③ 构建后 dist 扫描（禁区目录 + 文件名特征）。

## 七、基准设计（`benchmark/`）

| 基准 | 内容 | 真值来源 | 指标 |
|---|---|---|---|
| B1 门槛边界 | 办法门槛（1000 万/100 万）的"恰好等于/±1 人"枚举 + 义务类型分栏核对 | 规则包门槛值 ± 邻域 | 判定正确率 |
| B2 检查项自洽 | 条款引用完整性、四态逻辑覆盖、证据要求非空 | 规则包自身 | 断言通过率 |
| B3 合成场景 | 程序化构造带真值的审计场景（含门槛分栏结论对账 + 逐项四态对账） | `data/truth/`（生成器产出，含 `expected.item_states`） | 触发判定准确率 / 四态判定准确率 / 误报率 / 漏报率 |
| B4 四态判定覆盖（M2） | auto 项映射词表逐值核对（引擎 vs 独立实现）+ 缺项口径回归锁 + 汇总语义 | 规则包 `auto_mapping` + 汇总语义（`cases.expected_summary`） | 映射一致率 / 缺项口径正确率 |

**真值语义单一实现源**：`benchmark/cases.py` 的 `expected_summary()` / `observed_nonpass()` /
`expected_item_states()` / `confusion()` 供测试与基准共用（防"基准说达标、测试说不过"的双口径漂移）。
**误报率口径（M4 固化）**：`confusion()` 是**唯一实现源**——二元口径 **问题 = `partial` ∪ `noncompliant`**
（`FLAGGED_STATES`）；误报=真值非问题而引擎判问题，**误报率 = 误报数 ÷ 真值非问题项数**；漏报率对称
（分母 0 记 0）。真值取真值库冻结的 `expected.item_states`（生成期独立推导），基准期**不现算真值**
（避免"引擎算真值再自比"的自证循环）。
**门指标（M4）**：`trigger_accuracy` ≥ 0.95、`state_accuracy` ≥ 0.95、`false_positive_rate` = 0
（常量在 `cases.GATE_*`，`bench --json` 的 `gates` 回显）；无样本指标不阻塞门禁（"无证据"≠"不达标"）。
**不许改真值凑引擎**：发现引擎与真值冲突 → 先判定谁对（回查条款/门槛语义）→ 修代码而非改真值；确认真值错则记录理由后改真值。
