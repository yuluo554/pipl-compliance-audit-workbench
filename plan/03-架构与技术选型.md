# 03 架构与技术选型

> 上游：[02-需求解读.md](02-需求解读.md)。本文定分层架构、零依赖核心层边界、证据存储、目录布局。
> 版本：v1（M0 定稿，2026-10-13）

## 一、技术选型

| 维度 | 选型 | 理由 |
|---|---|---|
| 语言 | Python 3.12+（开发机 3.12.10） | D-3 决策：3.8 已 EOL（2024-10-07），下限抬到 3.12 与实测环境一致 |
| 核心层依赖 | **仅标准库**（json/dataclasses/hashlib/argparse/pathlib/datetime） | NFR-4：核心可复现、零 API 依赖、基准离线可跑、脱敏面无外部调用 |
| CLI | `argparse`（标准库） | 零依赖；退出码语义可锁进测试 |
| 桌面 | PySide6（optional extra `[gui]`） | 沿用系列；只消费引擎 API |
| 文档导出 | Markdown 核心（零依赖）+ python-docx/openpyxl（optional extra `[report]`） | 冻结态提示按 `is_frozen()` 分流 |
| 打包 | PyInstaller onedir 双 exe（extra `[pkg]`） | 沿用系列惯例 |
| LLM | **不使用**（决策见 plan/06） | 领域为纯确定性规则 + 结构化输入，无解析兜底需求 → 全链路零 LLM，结论 100% 可复现 |
| 测试 | pytest（dev extra） | 沿用系列 |
| CI | GitHub Actions windows/ubuntu × py3.12 + `gui-smoke`（windows，offscreen） | D-3 决策：去掉 EOL 的 3.8；GUI 冒烟从"永远跳过"改为真跑 |

## 二、分层架构

```
┌─────────────────────────────────────────────────────────────┐
│ 表现层（薄，零判定逻辑）                                        │
│   cli.py（argparse，子命令）        gui/（PySide6，optional）  │
└───────────────┬─────────────────────────────┬───────────────┘
                │  只调 engine/pipeline 编排 API（同一事实源）      │
┌───────────────▼─────────────────────────────▼───────────────┐
│ 编排层 engine/pipeline.py                                    │
│   AuditRequest → compute_audit() → AuditResult               │
│   （门槛判定 + 检查单评估 + 分级汇总，CLI/GUI 共用同一编排）      │
└───────┬───────────────┬───────────────┬───────────────┬─────┘
        │               │               │               │
┌───────▼──────┐ ┌──────▼───────┐ ┌─────▼──────┐ ┌──────▼──────┐
│ rules/       │ │ engine/      │ │ evidence/  │ │ report/     │
│ 规则加载器    │ │ thresholds   │ │ 证据链      │ │ markdown    │
│ status 门控   │ │ checklist    │ │ sha256 指纹 │ │ docx/xlsx   │
│ （单点生效门）│ │ 四态判定      │ │ 底稿导出导入 │ │ (optional)  │
└───────┬──────┘ └──────────────┘ └────────────┘ └─────────────┘
        │
┌───────▼─────────────────────────────────────────────────────┐
│ 数据层（冻结产物，禁手改，生成器产出）                          │
│   data/rules/（依据×版本）  data/checklists/  data/truth/      │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ benchmark/（零 API 依赖，仅依赖核心层）                         │
│   cases.py（真值语义单一实现源）  runner.py（四类 runner）      │
└─────────────────────────────────────────────────────────────┘
```

**核心纪律**：
- 表现层（cli/gui）**零判定逻辑**，只做参数解析/渲染/通知；判定全部在 engine 层。
- `engine/pipeline.py` 是**唯一编排源**：CLI 与 GUI 共用 `compute_audit()`，不各写一套（防"单件与批量结论不同"的口径漂移）。
- `rules/loader.py` 的 `effective_ruleset()` 是**单点生效门**：`status=pending` 条目在此被拒，任何下游通路都拿不到未核对条目。
- 核心层（rules/engine/evidence/report-markdown/benchmark）**不得 import** PySide6/python-docx/openpyxl（AST 静态守门）。

## 三、规则包与数据模型（概览，详设见 04）

**规则包 = `data/rules/ruleset-<依据>-<版本>.json`**，顶层含：
- `meta`：`ruleset_id`、`basis`（依据清单）、`version`、`generated_at`（生成时间由生成器固定，非系统时钟）、`schema_version`；
- `thresholds`：门槛规则数组（param/op/value/结论/依据条款/status）；
- `checklist`：检查项数组（id/类别/层级/依据条款/核查方式/判定标准/证据要求/status）。

**每条数值/条款挂 `status`**：`verified`（已挂原文核对，含 `source`{渠道,url,核对日期}）或 `pending`（待核对，不入判定路径）。

## 四、判定语义（引擎侧，详设见 04）

汇总级状态枚举（与"没查出问题 ≠ 没检查过"对齐）：

| 汇总状态 | 含义 | 触发条件 |
|---|---|---|
| `triggered` / `not_triggered` | 触发 / 未触发审计义务 | 门槛引擎判定 |
| `compliant` | 全部适用项均符合 | 所有 applicable 项 = compliant |
| `partial` / `noncompliant` | 存在部分符合 / 不符合 | 适用项中有 partial / noncompliant |
| `not_assessed` | **未评估** | 无任何 applicable 项被评（全 skipped/unknown） |

单项状态枚举：`compliant` / `partial` / `noncompliant` / `not_applicable`（=skipped）/ `unknown`（未观测）。

## 五、证据链设计

- **证据条目模型**：`{evidence_id, item_id, source(来源说明), collected_at(采集时间), owner(责任人), file_ref(本地文件引用/结构说明), size, sha256}`。
- **指纹固化**：证据条目 sha256 随底稿固化；底稿导出产物自身也计算 sha256 进 `evidence.json`（"底稿被改动即可检出"）。
- **底稿**：单个 JSON 文件（`draft`），含审计范围、参数卡、各检查项结论与证据、整改台账；可整体导出/导入，支持跨会话续做。
- **脱敏**：证据仅存结构说明与指纹，不落真实内容副本；文件引用路径按脱敏纪律登记（本地路径不写入报告正文）。

**CLI 命令**（`paudit`，退出码语义定稿后锁进测试）：

| 子命令 | 作用 | 退出码 |
|---|---|---|
| `check <输入JSON>` | 单件：跑门槛+检查单，输出结论 | 0=完成 / 1=检出非合规或未评估 / 2=输入不可用 |
| `scan <目录>` | 批量：多场景扫描（失败隔离，失败件单列不改退出码） | 同上（失败件≠违规） |
| `report <底稿JSON> -o <输出>` | 导出报告（md/docx/xlsx） | 0=完成 / 2=输入不可用 |
| `bench` | 跑四类基准 | 0=达标 / 1=未达标或门控拦截 / 2=用法错误 |
| `gui` | 起桌面应用（惰性导入，缺 extra exit 3） | 0 / 2 / 3 |

## 七、确定性纪律（贯穿）

- 生成器自研**确定性 RNG**（splitmix64），禁 stdlib `random`、禁 `set` 迭代序、禁系统时钟；
- 落盘产物**无时间戳**（报告头的时间来自参数卡/底稿显式字段，不取 `datetime.now()`）；
- 两次运行/构建**逐字节一致**，配"再生成位级一致"守门测试；
- `.gitattributes` `* text=auto eol=lf` + "冻结 fixtures 出现 CR 即失败"守门；
- 报告产物逐字节可复现（文本行尾 / zip 容器 / 压缩流 / 文档属性时间戳逐类审一遍）。
